# Implement: clean base + plan seed

**Slug:** implement-base-seed · **Date:** 2026-08-25 · **Status:** implemented

## Goal

Two loop-hardening fixes surfaced by `work/ds-collab-retro.md`, both of which caused
manual rework during the `notebook-collision-policy` release:

1. **Base drift.** `worktree.sh add` branches new `wt/<slug>` from the current checkout
   HEAD (`scripts/worktree.sh:28`, `git worktree add -b` with no start-point). When the
   session is on a feature branch, the implementation branch inherits unrelated commits, so
   the `/3-review` diff and the `origin/main`-ancestor release precondition both break until
   someone rebases `--onto origin/main` by hand.
2. **Plan doesn't flow to the single-agent worktree.** `fan-exec.sh` seeds `work/<slug>/`
   into its worktrees (`seed_work_dir`, `scripts/fan-exec.sh:30`), but the single-agent path
   (`agent-exec.sh`) does not. `release.sh` then refuses (missing plan / dirty tree) until
   the plan is committed onto the branch by hand.

Done = new implementation branches start from `origin/main`, and `work/<slug>/plan.md` lands on
the final branch automatically for **both** the single-agent path and fan's `adopt`, with no
manual rebase or plan-commit step before `/4-release`.

**Both fixes land in `scripts/worktree.sh add`** — the single choke point every path passes
through (single-agent step 1, fan's per-sample `add <slug>-fan-N`, and fan's `adopt`
`add <slug>`). They are causally coupled: fix 1 alone makes things *worse*. Today branches
inherit checkout HEAD, so a plan.md committed on the current branch rides along for free;
once branches come from `origin/main`, that free ride disappears for **both** single-agent
and fan (`adopt`), making fix 2 mandatory for both — see reviewer finding, round 1.

- **Fix 1 — clean base.** On the new-branch creation path (`worktree.sh:28`), `git fetch origin`
  (best-effort) then branch from `origin/main` when that ref exists, else current HEAD. The
  resume path (line 26, existing `wt/<slug>`) is untouched.
  - *Fetch-failure behavior (explicit):* branch from the local `origin/main` ref whenever it
    exists, even if the fetch failed — a stale `origin/main` is accepted over falling back to
    HEAD, because HEAD is the very thing base-drift is protecting against. HEAD fallback fires
    only when no `origin/main` ref exists at all (no remote / never fetched). Documented, tested.
- **Fix 2 — seed + commit the plan, in `worktree.sh add`.** After the worktree exists (on
  **either** the new-branch or the resume path — `adopt` reaches `add` via resume, so the seed
  must run there too), if `work/<slug>/plan.md` exists in the repo root **and** is not already
  in the branch's HEAD tree (`git ls-tree` guard — idempotent, so resume/re-add/fan-adopt never
  double-commit), copy **only `work/<slug>/plan.md`** (never the whole `work/<slug>/` tree — that
  would drag `handoff.md`/`notes.md`/followup scratch onto the branch and into the `/3-review`
  diff) and make a "Record plan" commit. Both final-branch call sites — single-agent `add <slug>`
  and fan `adopt`'s `add <slug>` (fan-exec.sh:113, resume path) — pass the real slug, so one
  change covers both. Per-sample `add <slug>-fan-N` finds no `work/<slug>-fan-N/` and no-ops,
  leaving `fan-exec`'s uncommitted `seed_work_dir` (implementer context) untouched.
  - **Deliberate invariant change (Owner-approved, Broad scope):** committing `plan.md` onto the
    fan-adopted branch reverses the documented "seed kept out of the adopted diff" invariant
    (`ARCHI.md:18`), asserted by `tests/test-scripts.sh` "fan adopt preserves auto-committed
    sample work" (the `! grep -E '^work/demo/'` line). That assertion is rewritten to expect
    exactly `work/<slug>/plan.md` present and nothing else under `work/<slug>/`. Safe because
    fan **selection runs before `adopt`**, so a plan commit added at adopt time cannot influence
    which sample wins. ARCHI's line is regenerated by `/compact` at release, not hand-edited here.

Rejected — seed in `/2-implement` prose or `agent-exec.sh`: skill prose isn't mechanically
enforced and would miss fan's `adopt`; `agent-exec.sh` is per-run and would land the plan
uncommitted in the implementer's tree, risking capture in its diff. `worktree.sh` is the only
point that covers single-agent and fan symmetrically.

Trade-off accepted: this widens `worktree.sh`'s responsibility from pure worktree lifecycle to
"lifecycle + fetch + record-plan." Weighed against duplicating seed-and-commit into
`fan-exec.sh adopt` (which leaves the single-agent path needing separate handling and keeps
two copies of the logic), the single shared choke point wins. Note `worktree.sh`'s ARCHI
convention — "only asks git, never inspects `.git` directly" — is about linked-worktree
`.git`-as-file compatibility, **not** about avoiding network calls; `git fetch` is itself
"asking git" and does not violate it.

Acknowledged cost: under fan mode, `dispatch` calls `add` N times (once per sample, each on the
new-branch path → one `git fetch` each). `adopt`'s `add <slug>` hits the **resume** path (the
branch already exists after `git branch -f`, fan-exec.sh:112), which Fix 1 does not touch, so it
does **not** fetch — total fetches = N, not N+1. Fan mode is already sequential/N× wall-clock
(per ARCHI), so this is acceptable.

## Acceptance criteria

- [ ] **Base, feature-branch case:** in a hermetic bare-`origin` fixture, `worktree.sh add <slug>`
      run while the checkout is on a feature branch ahead of `main` creates `wt/<slug>` whose
      merge-base with `origin/main` equals `origin/main`'s tip (NOT carrying feature-branch commits).
- [ ] **Base, no-origin/main case:** with no `origin/main` ref, `add` still succeeds from HEAD.
- [ ] **Base, stale-ref-after-failed-fetch case:** with a local `origin/main` ref present but the
      remote unreachable, `add` branches from the (stale) `origin/main` ref, not HEAD.
- [ ] **Resume path unchanged:** re-adding an existing `wt/<slug>` checks out that branch; no
      duplicate "Record plan" commit (idempotent `git ls-tree` guard holds).
- [ ] **Seed, single-agent:** after `add <slug>` with `work/<slug>/plan.md` present in root,
      `git ls-tree -r wt/<slug> -- work/<slug>/plan.md` is non-empty and `git status --porcelain`
      in the worktree is clean.
- [ ] **Seed, fan-adopt:** in the fan fixture (extended with `origin/main`) with the plan NOT
      already on `origin/main`, after `fan-exec.sh adopt` the final `wt/<slug>` has
      `work/<slug>/plan.md` committed — and the adopted diff contains **no other** `work/<slug>/`
      file (the rewritten invariant assertion).
- [ ] **Existing fan checks intact:** the four other checks reusing `setup_fan_fixture` still
      pass after the fixture gains a remote.
- [ ] `bash scripts/gate.sh` green; `shellcheck scripts/worktree.sh` clean.
