# Architecture

_A snapshot of what the codebase IS — regenerated by `/init` and `/compact`, never hand-groomed._

## Stack

Bash (`set -uo pipefail`, macOS/Linux) and Markdown. No compiled language, no package manager. The "runtime" is Claude Code itself: skills orchestrate, agents review, shell scripts do the deterministic work. The implementer runtime is a one-line `config.yaml` swap (`codex` here; `claude` under the `work` profile). Only external tool the gate needs is `shellcheck`.

## Layout

- `CLAUDE.md` / `ARCHI.md` / `PLAN.md` — the hot context tier (loaded every session, ~300-line budget).
- `config.yaml` — the single knob: profile, per-role models (incl. `fan_selector`), implementer runtime, `implementer.fan` (best-of-N sample count; default 1 = single-agent), `reviewer.command` (the codex second reviewer, read from `main:config.yaml` at review time — branch config cannot choose the reviewer binary), gate command, worktree dir.
- `skills/` — the loop stages (`1-plan`…`5-retro`) plus `init` and `compact`. Each is a `SKILL.md`; `1-plan` and `2-implement` carry `prompts/*.tpl` (plan, handoff, followup). `5-retro` closes each unit: four questions, each lesson routed to exactly one of `mechanical`/`contextual`/`process`/`not worth keeping`, applied on a `wt/retro-<slug>` worktree (reused if it already exists; removed after the PR merges) that may touch only `knowledge/`, `PLAN.md`, and the retro file. `2-implement` also documents Fan Mode (N>1): dispatch N samples, gate-filter, adopt a winner. Exposed to Claude Code via the `.claude/skills → ../skills` symlink.
- `.claude/agents/` — fresh-subagent definitions (`plan-reviewer.md`, `code-reviewer.md`, `fan-selector.md`): read-only tools, separate model, cold context.
- `scripts/` — the deterministic layer: `gate.sh` (stack-detecting check runner), `worktree.sh` (isolated-checkout lifecycle: `add` best-effort-fetches and branches new `wt/<slug>` from `origin/main` — HEAD only when no `origin/main` ref exists — then idempotently commits `work/<slug>/plan.md` onto the branch so the plan flows to release; the resume path skips the fetch/base change), `agent-exec.sh` (dispatches the implementer into a worktree; normalizes the worktree path to absolute and fails `no new commit` only when the tree was clean before dispatch and a zero-exit dispatch leaves HEAD unchanged *and* the tree still clean — the produced-literally-nothing case), `codex-review.sh` (second-vendor code reviewer: pure reader run from the primary checkout, reads the plan body from the branch via `git show wt/<slug>:…` but `reviewer.command` from `main:config.yaml`, pipes plan+diff to the read-only reviewer, captures stdout to a temp file and moves it to `work/<slug>/codex-review.md` only on reviewer exit 0; verdict contract exit 0 = APPROVE / 1 = REQUEST CHANGES / 2 = tooling error, never a verdict), `fan-exec.sh` (best-of-N: `dispatch` spawns N sample worktrees, seeds `work/<slug>/` uncommitted, auto-commits each sample before the gate, prints a manifest of gate-passers; `adopt` retargets `wt/<slug>` to a chosen sample and force-cleans all `<slug>-fan-*` worktrees/branches), `release.sh` (release preconditions incl. the previous unit's non-empty `retro.md` + version/changelog/commit + `work/.last-released` marker on the release branch — the marker must be a regular file byte-identical to `origin/main`'s copy (`cmp`, symlinks refused; on bootstrap with no origin marker, a local marker must be non-empty single-line); never tags, never touches `main`, never pushes; `tag-after-merge` tags post-merge; rollback resets and cleans the marker). `gate.d/*.sh` are auto-run hooks (`test-scripts.sh` wires the smoke suite in); `gate.d/examples/` contains opt-in hygiene hooks for notebook outputs (`nb-clean.sh`) and data-science artifacts/local paths (`ds-hygiene.sh`).
- `VERSION` / `CHANGELOG.md` — CalVer (`YYYY.M.MICRO`) + Keep-a-Changelog; written only by `release.sh`.
- `profiles/` — `software` (base), `machine-learning` (eval-defines-done + notebook strategy + opt-in repo hygiene hook declaration for data/model artifacts and hardcoded local paths), `database`, `work` (Atlassian/Bitbucket: Claude implementer, Bitbucket CI, Jira reference-only, pointer to ML notebook/repo hygiene because profiles do not merge); selected by `config.yaml`'s `profile:`.
- `tests/test-scripts.sh` — smoke tests for the shell layer: release refusals + a rollback test (pre-commit-hook forced failure; the marker `git clean` insurance path itself is untestable at pre-commit granularity) + the PR-merge flow (bump-on-branch, `origin/main` collision guard, mid-gate re-check, `tag-after-merge` happy + wrong-commit refusal, refusal without either verdict sentinel, the retro refusal matrix + marker integrity cases (deleted/mutated/trailing-newline/symlinked/re-run markers, malformed bootstrap markers) + rollback cases), hermetic fan-exec cases (canned implementer over a real worktree + bare-remote topology), hermetic agent-exec cases (commit / uncommitted / produced-nothing / relative-path / cd-elsewhere / dirty-redispatch dispatches), `worktree.sh add` base/seed cases, `nb-clean.sh` and `ds-hygiene.sh` example-hook cases, and hermetic codex-review cases (canned reviewer: exit-code matrix with stderr substrings, main-sourced config + ignored branch override, parser termination + commented-command anchor, artifact-only write, worktree stays clean, failed reviewer preserves the prior artifact, missing-plan and wrong-checkout refusals).
- CI: `.github/workflows/ci.yml` (GitHub) and `bitbucket-pipelines.yml` (Bitbucket) both run the smoke suite + gate; the `work` profile keeps the Bitbucket one.
- `knowledge/` — cold-tier docs, loaded only on citation (empty but for a README); `work/<slug>/` — one directory per work unit (`plan.md` etc.).
- `AGENTS.md` — the contract the implementer subagent reads.

## Entry points

- **The loop:** `/1-plan` → `/2-implement` → `/3-review` → `/4-release` → `/5-retro`. Invoked as skills from the orchestrator session; full TRIP — release, push, PR, and tag run without an in-session Owner confirm. `/3-review` is dual-vendor: fresh Claude `code-reviewer` subagent + `scripts/codex-review.sh <slug>`, both APPROVE required, both sentinels recorded in one in-place commit on the worktree plan.
- **`scripts/gate.sh`** — run from anywhere in the tree; `cd`s to repo root, auto-detects stacks (Node/Python/Shell/Rust/Go), runs applicable checks + `gate.d/*.sh` hooks. Exit 0 = pass.
- **`scripts/release.sh <slug> [--confirm-delta <text>]`** — the release driver; also `check-version` / `next-version` / `tag-after-merge` subcommands. One universal PR-merge topology: fetch-guards `origin/main` (before and after the gate), commits the bump on the release branch, never merges/tags/pushes `main`. After the PR merges, `tag-after-merge <slug>` fetches, verifies `origin/main`'s tip is this release (its `VERSION` and `Release v<version>` subject), and creates the tag locally — the tag push is `/4-release`'s final autonomous step. A release also writes the slug to `work/.last-released` (in the release commit), and `check_previous_retro` refuses the *next* release while `work/<that-slug>/retro.md` is missing or empty, or while the branch's marker is a symlink, deleted, or not byte-identical to `origin/main`'s.
- **`scripts/worktree.sh add|remove|list <slug>`** — manages worktrees under `../agentic-coding-worktrees`; `add` bases new branches on `origin/main` and records the unit's `plan.md` onto the branch; **`scripts/agent-exec.sh <worktree> <handoff>`** — feeds a handoff to the implementer runtime inside one.
- **`scripts/fan-exec.sh dispatch <slug> <handoff> <N>` / `adopt <slug> <sample-branch>`** — the best-of-N primitive behind `2-implement`'s Fan Mode; sequential (N× wall-clock), activated only when `implementer.fan > 1`.

## Conventions

- **Writer never reviews.** Reviews come only from fresh `.claude/agents/` subagents (read-only, separate model). Never review a diff produced in your own thread.
- **The gate and release are scripts, and authoritative.** Never overrule `gate.sh` or `release.sh`; enforcement never lives in skill prose.
- **Implementation happens in worktrees, never in this checkout.** Use `worktree.sh`.
- **Verdict sentinels are distinct by stage and vendor:** `Plan verdict:`, `Code-review verdict:`, `Codex-review verdict:`; `release.sh` releases only on exact `Code-review verdict: APPROVE` **and** `Codex-review verdict: APPROVE` lines in the branch's plan. Exit ≥2 from `codex-review.sh` is a tooling error, never a verdict — no sentinel may be recorded from artifact prose after a non-zero exit.
- **Release preconditions** (all before anything irreversible; trap rollback after): APPROVE sentinel, gate green, `ARCHI.md` fresher than the last commit touching `scripts/ skills/ profiles/ config.yaml CLAUDE.md` (stale → `/compact`), version strictly increasing, and `origin/main` an ancestor of the release branch — re-checked after the gate to close the cross-release version collision.
- **`worktree.sh` only asks git** (`git worktree`, `git rev-parse`), never inspects `.git` directly — works from inside a worktree where `.git` is a file. Preserve this. **YAML parsing is naive awk** in `worktree.sh`/`agent-exec.sh`/`release.sh`; replace with `yq` only if it bites.
- All shell scripts must pass `shellcheck` (enforced by the gate). Use `set -uo pipefail`.
- Vendor/model names live only in `config.yaml`. Reviewer models are additionally in agent frontmatter, which is authoritative; config.yaml documents intent.
