# Architecture

_A snapshot of what the codebase IS — regenerated by `/init` and `/compact`, never hand-groomed._

## Stack

Bash (`set -uo pipefail`, macOS/Linux) and Markdown. No compiled language, no package manager. The "runtime" is Claude Code itself: skills orchestrate, agents review, shell scripts do the deterministic work. The implementer runtime is a one-line `config.yaml` swap (`codex` here; `claude` under the `work` profile). The gate declares `shellcheck` as a required tool.

## Layout

- `CLAUDE.md` / `ARCHI.md` / `PLAN.md` — the hot context tier (loaded every session, ~300-line budget).
- `config.yaml` — the single knob: profile, per-role models (incl. `fan_selector`), implementer runtime, `implementer.fan` (best-of-N sample count; default 1 = single-agent), `reviewer.command` (the codex second reviewer, read from `main:config.yaml` at review time — branch config cannot choose the reviewer binary), gate command and required tools, `archi.sources` (colon-separated freshness paths), optional `worktrees.dir` (defaults to `../<checkout-basename>-worktrees`).
- `harness/skills/` — the loop stages (`1-plan`…`5-retro`) plus `init`, `compact`, and `docs`. Each is a `SKILL.md`; `1-plan`, `2-implement`, and `docs` carry `prompts/*.tpl` (plan, handoff, followup; docs handoff). `5-retro` closes each unit: four questions, each lesson routed to exactly one of `mechanical`/`contextual`/`process`/`not worth keeping`, applied on a `wt/retro-<slug>` worktree (reused if it already exists; removed after the PR merges) that may touch only `knowledge/`, `PLAN.md`, and the retro file. `2-implement` also documents Fan Mode (N>1): dispatch N samples, gate-filter, adopt a winner. `harness/skills/docs` is the `/docs` documentation-writing stage: it dispatches codex/GPT through the two-arg `agent-exec.sh` to author/rewrite prose, ships by the small-fix path, and runs no gate/no self-review (its handoff fills the footprint from the plan and switches off the AGENTS.md gate rule; the writer summary lands in `work/<slug>/notes.md`). Installed per entry into `~/.claude/skills/` by `harness install`.
- `harness/agents/` (installed into `~/.claude/agents/`) — fresh-subagent definitions (`plan-reviewer.md`, `code-reviewer.md`, `fan-selector.md`): read-only tools, separate model, cold context.
- `harness/bin/harness` — location-independent dispatcher, resolving symlink chains; `root` prints the harness root. Scripts resolve project state through `scripts/lib/project.sh`, using the registry or the caller’s git toplevel.
- `harness/scripts/lib/stack.sh` — shared header-only `Stacked on:` lookup (branch plan, then primary/state plan), git `merge-base --fork-point`, and review-base selection. Unmerged parents use `wt/<parent>`; merge/fast-forward landings use the main ref; rewrites use the exact fork SHA with a restack command. Fork recovery is local: reflogs expire only during gc (unreachable entries after 30 days, reachable after 90 by default); expiry or another clone may expose old parent commits in review and make restacking conflict. Release still refuses an unlanded parent independently of reflogs.
- `harness/scripts/lib/project.sh` — shared resolver: primary-checkout registry lookup under `$HARNESS_HOME/projects/`, fallback to repo mode; linked worktrees share state. `project.sh` prints state/mode/root; `register.sh` normalizes `--subdir` (leading `./`, repeated and trailing slashes; rejects empty, `.` and `..` components), then creates excluded local imports and home-directory state after preflight.
- `harness/scripts/` — the deterministic layer: `install.sh` (idempotent per-entry home-directory links, preflights all non-symlink conflicts before writing), `gate.sh` (stack-detecting check runner), `demo.sh` (runs the first sh/bash fence in a plan's `## Demonstration`, respecting headings only outside fences; plain bash from the requested git worktree, streaming output; exit 0 pass or `None:`, 1 block failure or porcelain-status delta (untracked files listed individually), 2 plan/tooling error), `worktree.sh` (isolated-checkout lifecycle: `add` best-effort-fetches and branches new `wt/<slug>` from the header’s `wt/<parent>` when stacked, otherwise `origin/main` — HEAD only when no `origin/main` ref exists — then idempotently commits `work/<slug>/plan.md` onto the branch so the plan flows to release; `sync-artifacts` copies top-level regular non-dot primary `work/<slug>/` files, explicitly not symlinks, except `plan.md` into the worktree, then stages the whole `work/<slug>` directory minus `plan.md` so pre-existing worktree-side unit files are also captured, and commits only when staged unit changes exist; the resume path skips the fetch/base change), `agent-exec.sh` (prepends the required non-empty `harness/AGENTS.md` contract and a separator to the handoff in a temporary file, then dispatches the implementer into a worktree and commits leftovers after a successful dispatch (repo mode excludes `work/`, registry mode includes it; staged-diff guard skips empty commits, commit failures propagate); normalizes the worktree path to absolute and fails `no new commit` only when the tree was clean before dispatch and a zero-exit dispatch leaves HEAD unchanged *and* the tree still clean — the produced-literally-nothing case; `--allow-noop`, used by `/2-implement` followups, downgrades that to a note), `codex-review.sh` (second-vendor code reviewer: pure reader run from the primary checkout, reads the plan body from the branch via `git show wt/<slug>:…` but `reviewer.command` from `main:config.yaml`, uses `review_base` from `lib/stack.sh` for the diff so a stale local `main` can't pollute the review, pipes plan+diff excluding `work/<slug>` artifacts to the read-only reviewer, captures stdout to a temp file and moves it to `work/<slug>/codex-review.md` only on reviewer exit 0; verdict contract exit 0 = APPROVE / 1 = REQUEST CHANGES / 2 = tooling error, never a verdict), `fan-exec.sh` (best-of-N: `dispatch` refuses stacked plans, otherwise spawns N sample worktrees, seeds `work/<slug>/` uncommitted, auto-commits leftovers after failed dispatches before the gate (agent-exec owns successful-dispatch commits), prints a manifest of gate-passers; `adopt` retargets `wt/<slug>` to a chosen sample and force-cleans all `<slug>-fan-*` worktrees/branches), `release.sh` (release preconditions incl. the previous unit's non-empty `retro.md` + version/changelog/commit + `work/.last-released` marker on the release branch — the marker must be a regular file byte-identical to `origin/main`'s copy (`cmp`, symlinks refused; on bootstrap with no origin marker, a local marker must be non-empty single-line); never tags, never touches `main`, never pushes; `tag-after-merge` tags post-merge; rollback resets and cleans the marker), `state.sh` (read-only per-work-unit execution-state deriver: given a slug, prints flat `slug`/`stage`/`review`/`next_action` lines derived purely from observable facts — artifact presence under `work/<slug>/`, the whole-line verdict sentinels read from the branch plan via `git show wt/<slug>:…` when the branch exists else the primary plan, the `wt/<slug>` ref, and the `work/.last-released` marker; `review` is `approve` only when both `Code-review verdict: APPROVE` and `Codex-review verdict: APPROVE` are present; seven first-match-wins stage rules `plan→implement→review→release→done`; gate result is deliberately not derived, so `next_action` names `run harness gate` live; writes nothing), `archi-fresh.sh` (ref-aware ARCHI freshness check extracted from `release.sh`: `archi-fresh.sh [<ref>]` compares the last-commit epoch of `ARCHI.md` vs paths from `archi.sources` in `<ref>:config.yaml` (default `harness/ scripts/ config.yaml CLAUDE.md`) at `<ref>`, default `HEAD`; strict `<` = stale so equal epochs pass; exit 0 fresh / 1 stale naming the newer paths / 2 missing history; `--help` prints usage. `release.sh check_archi_fresh` delegates to it and `/3-review` runs it against `wt/<slug>` to catch staleness before release). `gate.d/*.sh` are auto-run hooks (`test-scripts.sh` wires the smoke and publish suites in); `harness/examples/gate.d/` contains opt-in hygiene hooks for notebook outputs (`nb-clean.sh`) and data-science artifacts/local paths (`ds-hygiene.sh`).
- `VERSION` / `CHANGELOG.md` — CalVer (`YYYY.M.MICRO`) + Keep-a-Changelog; written only by `release.sh`.
- `harness/profiles/` — `software` (base), `machine-learning` (eval-defines-done + notebook strategy + opt-in repo hygiene hook declaration for data/model artifacts and hardcoded local paths), `database`, `work` (Atlassian/Bitbucket: Claude implementer, local gate without committed CI, Jira reference-only, pointer to ML notebook/repo hygiene because profiles do not merge), `work-slim` (work data-science repos: explore / ship / loop lanes, PR description as the record, reuses `work`'s S3, Snowflake and Gate sections); selected by `config.yaml`'s `profile:`.
- `harness/tests/test-scripts.sh` — smoke tests for the shell layer: release refusals + a rollback test (pre-commit-hook forced failure; the marker `git clean` insurance path itself is untestable at pre-commit granularity) + the PR-merge flow (bump-on-branch, `origin/main` collision guard, mid-gate re-check, `tag-after-merge` happy + wrong-commit refusal, refusal without either verdict sentinel, the retro refusal matrix + marker integrity cases (deleted/mutated/trailing-newline/symlinked/re-run markers, malformed bootstrap markers) + rollback cases), hermetic fan-exec cases (canned implementer over a real worktree + bare-remote topology), hermetic agent-exec cases (commit / uncommitted / produced-nothing / allow-noop / relative-path / cd-elsewhere / dirty-redispatch dispatches; auto-commit additions/modifications/deletions, repo `work/` exclusion and work-only no-commit, registry `work/` inclusion, non-zero dispatch no-commit, fan commit subject, working-tree lint deletion/untracked/ignored cases), `worktree.sh add` base/seed cases, `worktree.sh sync-artifacts` artifact-capture/refusal cases, `nb-clean.sh` and `ds-hygiene.sh` example-hook cases, hermetic demo cases (first-block/section scoping, headings inside fences, bash fences, cwd/default dir, plain bash, failure code, dirty-tree refusal, None, missing/empty plan sections, non-git directory, help/arguments), and hermetic codex-review cases (canned reviewer: exit-code matrix with stderr substrings, main-sourced config + ignored branch override, parser termination + commented-command anchor, artifact-only write, worktree stays clean, failed reviewer preserves the prior artifact, missing-plan and wrong-checkout refusals).
- `scripts/publish.sh` — dogfood-only, no args; requires HEAD's literal `v<VERSION>` tag, archives only committed `harness/`, README and LICENSE, then clones `TEMPLATE_REPO` and replaces its tree on `template-sync/v<version>`. Keeps prior history, prints clone path and branch, never pushes; removes the export temp dir, and removes the clone when up to date. Exit 0 success/up-to-date / 1 refusal / 2 tooling error.
- `harness/skeleton/` — starting config, ARCHI/PLAN, header-only CHANGELOG and bootstrap VERSION. `/init` copies missing files without overwriting (VERSION/CHANGELOG in repo mode only), and writes or appends missing hot-tier imports to repo-mode CLAUDE.md.
- `tests/test-publish.sh` — committed working-tree fixtures verify exact published tree, history, no push, HEAD isolation, tags, cleanup and a published-skeleton consumer's gate/freshness.
- CI: `.github/workflows/ci.yml` runs this repo's smoke suite + gate; consumers receive no CI workflow and run the gate locally.
- `knowledge/` — cold-tier docs, loaded only on citation (empty but for a README); `work/<slug>/` — one directory per work unit (`plan.md` etc.).
- `harness/AGENTS.md` — the contract sent ahead of every implementer handoff; carries a build-discipline ladder (lazy/YAGNI: reuse → stdlib → native → installed dep → one line → minimum code, run after understanding the problem) so the implementer builds the leanest working diff within scope, with explicit validation/security/error-handling boundaries never simplified away.

## Entry points

- **The loop:** `/1-plan` → `/2-implement` → `/3-review` → `/4-release` → `/5-retro`. Invoked as skills from the orchestrator session; full TRIP — release, push, PR, and tag run without an in-session Owner confirm; `/4-release` checks README drift before pushing (README is published, so it never names dogfood-only scripts). `/3-review` is dual-vendor: fresh Claude `code-reviewer` subagent + `harness codex-review <slug>`, both APPROVE required, both sentinels recorded in one in-place commit on the worktree plan. Both review paths use `harness worktree base` / shared `review_base`, preserving child-only diffs across parent rewrites and landings (Decision 2026-09-01). Both reviewers gate the verdict on severity: only CRITICAL/HIGH findings force `REQUEST CHANGES` (in any round); MEDIUM and LOW never set the verdict — MEDIUM is orchestrator-routed (fix / send back if load-bearing / defer), so a criteria-meeting diff approves without burning the 3-round cap.
- **`harness gate`** — run from anywhere in the tree; `cd`s to repo root, auto-detects stacks (Node/Python/Shell/Rust/Go), runs applicable checks + `gate.d/*.sh` hooks. Exit 0 = pass.
- **`scripts/publish.sh`** — prepare the harness-only public sync commit from a tagged HEAD; publishing belongs to `/4-release`.
- **`harness demo <slug> [<dir>]`** — runs the plan demonstration from the orchestrator after agent-exec commits and the gate passes; the cold code-reviewer re-runs the branch copy and judges whether its output shows the goal. Plans require real inputs and writes only under `mktemp -d`; units with no runnable behavior may use `None: <reason>`.
- **`harness release <slug> [--confirm-delta <text>]`** — the release driver; also `check-version` / `next-version` / `tag-after-merge` subcommands. One universal PR-merge topology: first refuses stacks whose parent plan is absent on `origin/main`, or prints the exact `rebase --onto origin/main <fork>` command if parent commits remain; then fetch-guards `origin/main` (before and after the gate), commits the bump on the release branch, never merges/tags/pushes `main`. After the PR merges, `tag-after-merge <slug>` fetches, verifies `origin/main`'s tip is this release (its `VERSION` and `Release v<version>` subject), and creates the tag locally — the tag push is `/4-release`'s final autonomous step. A release also writes the slug to `work/.last-released` (in the release commit), and `check_previous_retro` refuses the *next* release while `work/<that-slug>/retro.md` is missing or empty, or while the branch's marker is a symlink, deleted, or not byte-identical to `origin/main`'s.
- **`harness worktree add|base|remove|sync-artifacts|list <slug>`** — manages worktrees under `worktrees.dir`, defaulting to `../<checkout-basename>-worktrees` (invoke add/remove from the primary checkout); `base` prints the review base or fails explicitly for missing stack refs; `add` bases stacked branches on local `wt/<parent>`, otherwise `origin/main` and records the unit's `plan.md` onto the branch; `sync-artifacts` records primary-checkout work artifacts on the unit branch without overwriting the worktree plan; **`harness agent-exec <worktree> <handoff>`** — feeds a handoff to the implementer runtime inside one.
- **`harness state <slug>`** — prints the work unit's derived execution state (`stage`/`review`/`next_action`) so a cold session learns where a unit stands and what comes next without the prior conversation; read-only, gate result out of scope by design.
- **`harness fan-exec dispatch <slug> <handoff> <N>` / `adopt <slug> <sample-branch>`** — the best-of-N primitive behind `2-implement`'s Fan Mode; sequential (N× wall-clock), activated only when `implementer.fan > 1`.

Registry mode: gate hooks/config and unit artifacts live in the state dir; gate, agent-exec and demo run in the project subfolder. Worktree add never commits plans and sync-artifacts is a no-op. State stops at review; codex-review, release and fan-exec refuse pending reviewer-set/pr-release. ARCHI freshness compares state-file mtime to project source commits. Repo mode retains the behavior described above.

## Key flows

After the release tag push, `/4-release` cleans matching untracked unit copies and pulls with `--ff-only`, then runs `harness install` to refresh entry links. When `scripts/publish.sh` exists, it prepares the template sync commit; the skill pushes from the printed clone, opens a PR, closes superseded sync PRs, and merges with `gh pr merge --rebase` without CI.

## Conventions

- **Writer never reviews.** Reviews come only from fresh `harness/agents/` subagents (installed into `~/.claude/agents/`) (read-only, separate model). Never review a diff produced in your own thread.
- **The gate and release are scripts, and authoritative.** Never overrule `gate.sh` or `release.sh`; enforcement never lives in skill prose.
- **Implementation happens in worktrees, never in this checkout.** Use `worktree.sh`.
- **Verdict sentinels are distinct by stage and vendor:** `Plan verdict:`, `Code-review verdict:`, `Codex-review verdict:`; `release.sh` releases only on exact `Code-review verdict: APPROVE` **and** `Codex-review verdict: APPROVE` lines in the branch's plan. Exit ≥2 from `codex-review.sh` is a tooling error, never a verdict — no sentinel may be recorded from artifact prose after a non-zero exit.
- **Release preconditions** (all before anything irreversible; trap rollback after): APPROVE sentinel, gate green, `ARCHI.md` fresher than the last commit touching the ref’s `archi.sources` paths (default `harness/ scripts/ config.yaml CLAUDE.md`) (via `harness archi-fresh`; `/3-review` runs the same check earlier and heals staleness with a targeted branch edit, so release rarely trips it), version strictly increasing, and `origin/main` an ancestor of the release branch — re-checked after the gate to close the cross-release version collision.
- **`worktree.sh` only asks git** (`git worktree`, `git rev-parse`), never inspects `.git` directly — works from inside a worktree where `.git` is a file. Preserve this. **YAML parsing is naive awk** in `gate.sh`/`worktree.sh`/`agent-exec.sh`/`release.sh`/`archi-fresh.sh`; `gate.sh` and `archi-fresh.sh` are section-scoped, not depth-aware; replace with `yq` only if it bites.
- All shell scripts must pass `shellcheck` (enforced by the gate). Use `set -uo pipefail`. CI pins shellcheck 0.11.0 (`.github/workflows/ci.yml`) to match local; indirectly invoked test functions still disable both `SC2317` and `SC2329` so older local shellcheck (<0.10) stays clean.
- Vendor/model names live only in `config.yaml`. Reviewer models are additionally in agent frontmatter, which is authoritative; config.yaml documents intent.
